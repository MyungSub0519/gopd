# 기본 PDF 반환 API

이 문서는 초기 기본 API 설계 기록입니다. 현재 기본 응답의 필드와 배열 구성은 [페이지별 기본 PDF 응답 설계](2026-09-15-page-grouped-basic-pdf-design.md)를 따릅니다.

## 승인된 요구

`cmd/gopd/main.go`에서 파일 경로를 받는 `pdfparse(path)` 한 번으로 기본 PDF 객체를 반환한다. 나머지 정보는 상세 분석 기능으로 보존한다. 텍스트는 글꼴 기본 정보를 직접 참조하고 이미지 배치는 공유 리소스를 직접 참조한다.

## API와 데이터 경계

- `pdf.ParsePDF(path string) (*PDF, error)`가 기본 공개 진입점이다.
- CLI의 `pdfparse(path string) (*pdf.PDF, error)`는 이 함수를 호출한다.
- `PDF`의 공개 필드는 `Pages`, `Texts`, `Graphics`, `Images`, `Diagnostics`이다.
- `PDF.Details() *DetailedPDF`는 같은 파싱에서 얻은 상세 결과를 제공한다.
- 기존 `Open`, `Read`, `BuildPDF`는 상세 동작을 유지하고 반환 타입 이름을 `DetailedPDF`로 바꾼다. `Parse`, `ParseFile` 등의 저수준 함수는 그대로 유지한다.
- 기존 상세 요소 타입은 `DetailedPage`, `DetailedText`, `DetailedGraphic`, `DetailedImage`, `DetailedPathSegment`로 구분한다.
- 기본 `Page`는 영역·회전·단위·그리기 순서·해석 상태를 제공한다.
- 기본 `Text`는 페이지 인덱스·Unicode·공유 `FontInfo`·크기·행렬·표시 방식·스타일·해석 상태를 제공한다.
- 기본 `Graphic`은 페이지 인덱스·좌표 경로·그리기 방식·스타일을 제공한다. 경로에 바이트 범위를 넣지 않는다.
- 기본 `Image`는 페이지 인덱스·행렬·공유 `ImageInfo`·스타일을 제공한다.
- 기본 스타일은 색상·선 설정·불투명도·혼합 방식과 `Clipped`, `Complete` 표시를 제공한다. 전체 클리핑 경로와 CTM은 상세 상태에 남긴다.
- 글꼴은 상세 결과의 리소스 인덱스로 공유한다. 이름이 같아도 서로 다른 객체이면 합치지 않는다.
- 기본 진단에는 페이지 인덱스, 심각도, 코드, 설명을 넣는다. 문서 전체 진단의 페이지는 `-1`이다. 상세 진단에는 바이트 출처가 남는다.

## 동작과 제한

- 표준 `encoding/json`으로 기본 객체를 저장하면 원본 객체·명령·글리프·바이트 범위·CMap·스트림이 노출되지 않는다.
- 기본 배열 인덱스는 상세 배열과 대응한다. 같은 페이지의 요소 그리기 순서를 보존한다.
- 기본 필드의 가변 슬라이스는 상세 결과와 분리한다. 공유 기본 글꼴·이미지 정보는 읽기 전용으로 취급한다.
- 파일 읽기/파싱 오류를 호출자에게 전달한다. 상세 파싱이 부분 결과와 오류를 반환하면 기본 부분 결과와 같은 오류를 반환한다.
- 상세 결과는 처음 파싱할 때 생성하고 보관한다. 이번 작업은 결과/API 분리이며 선택적 파싱이나 메모리 사용량 감소를 보장하지 않는다.
- Go 1.25 이상, 표준 라이브러리만 사용한다.
- CLI의 기존 텍스트·개수 출력은 유지한다. 개수 출력에 필요한 상세 리소스 수는 `Details()`에서 조회한다.

## 검증

합성 PDF로 콘텐츠 수·그리기 순서·Unicode·행렬·공유 리소스·동명 글꼴 분리·오류 전달·진단 페이지를 확인한다. 기본 JSON에 상세 키가 누출되지 않는지 확인하고 기존 전체 테스트와 `go vet`를 실행한다.
